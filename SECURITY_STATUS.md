## Guided installer boundaries

The guided setup uses owner-only state, unique generated credentials, exact TLS identities, separate database roles and isolated Docker project names. Local evaluation can explicitly use a reduced-hardening loopback profile on incompatible hosts; server setup refuses that exception. ## Implemented and locally exercised

- RFC 9420 suite 0x0001 through OpenMLS 0.9.2/RustCrypto: X25519, AES-128-GCM, SHA-256 and Ed25519. Public MLS KeyPackages/wire bindings are checked by a bounded native executable; servers receive no private provider snapshots.
- Client independent device fingerprint pins, signed genesis/ordered headers and authorized full-roster transitions; actual MLS roster and epoch-authenticator hash are checked independently of delivery metadata.
- Speculative membership state is retained in an encrypted outbox; active state advances after authenticated acceptance. Concurrent accepted commits force reconciliation and explicit retry. Cancellation cannot recall an already accepted request; reconciliation must establish its outcome.
- Encrypted IndexedDB state/outbox with revision comparison and cross-tab Web Locks. Lock checks fence both sides of asynchronous persistence and clear retained candidate/upload references. Local secret uses worker-based Argon2id (64 MiB, three passes, one lane); derived key remains in worker memory while unlocked, fresh random AEAD nonce on each save. Physical phone KDF tuning remains unqualified.
- One-use enrollment approval, fresh session challenge signatures, unique/expired KeyPackage rejection, automatic replacement package after a verified join. Revocation pauses group writes until an authorized MLS removal/rekey.
- High-entropy pre-provisioned recovery authority resets all old devices and generates fresh MLS credentials. Old history becomes local-only. Restored ratchets are never resumed. Additional-device history imports copy only authenticated event data, not keys, cursors, pins or pending sends.
- XChaCha20-Poly1305 file chunks with independent 32-byte key, random 16-byte prefix plus 64-bit chunk counter; AAD binds version, conversation, attachment, index and count. File key/name/MIME travel inside MLS application data. Ciphertext chunks are stored in PostgreSQL; this deliberate storage deviation requires capacity qualification.
- Secure opaque cookies, CSRF/Origin checks, per-resource authorization, bounded bodies/frames/chunks, rate limits, inert React text, nonce CSP and same-origin assets. Runtime DB role is distinct from bootstrap/migration roles; DDL/escalation/migration-history writes were denied in the staging check.
- Durable PostgreSQL commit before ACK and transactional notification outbox. Redis loss does not erase envelopes; existing-session HTTP reads can continue, while rate-limited writes fail closed if Redis is unavailable.

## Optional device-assisted vault unlock

An unlocked user can opt into a local WebAuthn PRF wrapper on a compatible **trusted HTTPS hostname**. A fresh user-verified assertion must return a 32-byte PRF value before the encrypted local copy of the vault passphrase can be decrypted. Account login, MLS state, Argon2id vault sealing, device approval and recovery remain separate. Direct-IP origins, including the current `https://127.0.0.1:8445/` review URL, are excluded by the WebAuthn RP-ID host rule; the UI keeps passphrase/password-manager unlock and explains the limitation. A passkey can sync through its provider and device PIN can satisfy verification; the feature is not proof of a hardware-bound biometric key. No physical Face ID/Touch ID or independent integration review has occurred. A hostname switch changes browser origin and cannot silently migrate existing vaults. See ADR 0009 and TEST_REPORT.md. Release remains **BLOCKED**.

## Release blockers and limits

1. **Independent cryptographic/application review and penetration test absent.** Upstream tests and audited primitives do not independently verify HAVEN's adapter, integration, attachment construction, recovery, ordering or browser code distribution.
2. **Physical iOS Safari/Android and private-root trust not qualified.** Desktop Chrome/Firefox and isolated Linux WebKit results are not physical Safari/OS trust results. Low-memory devices, storage eviction, microphone permission behavior, background suspension and KDF performance need real-device testing.
3. **No public host or mobile-network qualification.** Stable primary/standby public IPs, valid issued IP certificates, two provider failure domains, clock policy and prepared trust require operator infrastructure. No actual public IP is invented. Public Let's Encrypt IP certificates have a 160-hour lifetime; outside renewal may become unavailable.
4. **Production failover/offline installation not qualified.** A local streaming standby, explicit primary stop, promotion and matching ciphertext/order were tested. The source build used prepared dependencies with network-disabled build steps. Neither proves separate-provider fencing, private-tunnel/TLS replication, fresh-host air-gap installation, production RPO/RTO. A separate local two-IP browser drill now verifies prepared distinct devices through a TLS bridge and fenced promotion; it is not a provider/phone test.
5. **Capacity/endurance unqualified.** No 500-session/20-message-per-second qualification, lower-end phone benchmark or two-hour soak on a reference host. Quotas are safety bounds, not capacity evidence. Complete randomized protocol/property/fuzz and sensitive-exception matrices remain outstanding.
6. **Supply-chain findings remain visible.** Application npm and Python dependency scans report no findings in the recorded run. After moving app images to pinned Debian 13 bases and removing unused runtime package managers, Trivy reports API 44 HIGH/58 MEDIUM/61 LOW/1 UNKNOWN and web 43 HIGH/58 MEDIUM/60 LOW/1 UNKNOWN; zero critical and no fixed versions are listed. These remaining OS findings require applicability/maintainer triage and remain release limitations. A missing fix is not a security pass. The provider remediation below resolved the earlier Rust vulnerability entries. A fresh Cargo audit still retains the optional proc-macro-error2 maintenance warning. Python audits now cover development tools as well as runtime packages; Daphne and its vulnerable Twisted/Autobahn dependency chain have been removed. No clean-container or independent-review claim follows from application dependency results. See audit files and third-party notices.
7. **This Docker host cannot exercise the production no-new-privileges profile.** The explicit local overlay removes that option and binds ingress to loopback. Hardened production deployment must be tested on the actual host.
8. **Platform support is limited.** Prepared server/native-verifier artifacts target Linux x86_64. Other server architectures require a matching verifier build and full retesting; no incompatible binary fallback is allowed.
9. **Acceptance matrix is incomplete.** The controls CSV retains BLOCKED where the full criterion has not been executed, even when a useful local subcheck passed. Bounded local operational counters exist; broad adversarial/resource and production telemetry qualification remain incomplete.

## Residual risks, even after review

A compromised origin can replace JS/WASM and collect keys/plaintext. CSP, signed offline bundles and reproducible source review do not remove this browser trust boundary. Endpoint compromise, extensions, coercion, screenshots and recipient copies remain outside protection. Server/network observers see account/device IDs, routing, membership/roles, IPs, timing, sizes and optional typing/presence metadata. No anonymity claim.

Signed hash-chain checkpoints detect contradictions relative to retained client state. They are not independent key transparency or global fork prevention: mutually censored server forks may remain invisible until contradictory signed history/checkpoints meet. Local whole-snapshot rollback remains possible at the raw library boundary, as the characterization test demonstrates. Recovery must create fresh identity/ratchets. Never interpret that characterization test as a passing rollback-prevention invariant.

Browser GC and immutable JS/WASM snapshots prevent a reliable secure-erasure guarantee. Clearing a vault does not erase copies, swap, downloads, screenshots or a recovered older encrypted backup. Encrypted history exports preserve sensitive data and must be protected. New identities require independent peer verification and explicit group re-addition. If the final group authority is lost, create and verify a replacement group rather than silently granting authority.

A private root extends device trust beyond this site. Root compromise requires replacement on every device; leaf rotation alone is insufficient. There is no insecure HTTP or certificate-error bypass. No network route means no remote delivery.

## View-once media (engineering implementation)

Current retention changes are documented below and in ADR 0006: permanent opening timestamps have been removed, and the server retains temporary lease state only while needed.

Photo/video opening is consumed once per recipient account in PostgreSQL, with a device-bound temporary download session, local tombstone and no normal cache/export/replay path. This is cooperating-client behavior and server access control, not cryptographic remote deletion. Modified clients, screen capture, retained keys/ciphertext, old vault/server backups, stale database promotion, browser/decoder/GPU memory and compromised endpoints remain outside the guarantee. Opening can be consumed before any media is displayed. The server learns opening access even with optional read receipts off. See docs/adr/0005-view-once-media.md and the exact tests in TEST_REPORT.md. Physical Safari/Android and an independent review of this feature have not occurred. Overall release remains BLOCKED.

## Minimal server retention (engineering hardening)

Delivered application ciphertext is retired after a minimum 24-hour acceptance age only after every eligible active device durably ACKs; precise receipt timestamps are cleared. Unsynchronized ciphertext, all MLS control material and signed proofs remain. Attachments have a seven-day lifetime (including existing records capped by migration); abandoned uploads one hour. View-once no longer stores a permanent opening timestamp, ended capabilities/device bindings are cleared, and individual recipient records are removed when all openings finish. Replay tombstones remain. Sessions/invitations/challenges/notification metadata are cleaned promptly; security audit retention is seven days, without successful-login audit trails. A separate five-minute worker performs bounded cleanup on the sole writer.

Ingress strips client address headers; IPs remain observable in live ingress/kernel/provider state. Keyed minute-scoped Redis rate labels replace enumerable unkeyed labels. JSON-only Redis cache decoding replaces pickle, with a separate cache namespace and bounded timeouts. Supplied PostgreSQL logging/process-title and Nginx spooling/logging controls reduce accidental retention, not hostile-root observation. Accounts, public credentials, conversation membership and signed sender/order proofs remain database-visible. Existing backups/WAL/snapshots are not securely erased. Backup rotation tooling is dry-run by default and preserves minimum recovery copies. A stolen database is **not** metadata-free. See docs/security/server-data-retention.md and ADR 0006. This changes neither browser-origin trust nor independent-review/release gates.

## Guided first chat and member invitation policy

The guide reduces manual device-ID entry without changing MLS, device approval or independent fingerprint verification. Friend links require same-origin trusted HTTPS, bounded versioned public credentials, a matching current public-key fingerprint and explicit comparison of the full code through another trusted channel. Saved identity changes stop the guide. Neither signup nor link opening automatically pins another person. Contact names and retryable direct-chat intents are stored in the encrypted local vault.

At the owner's request, approved proof-bound ordinary members may now issue at most three one-use signup invitations per UTC day, at most three pending, with a 24-hour maximum lifetime. This deliberately expands the original administrator-only invitation policy. User-row locking serializes quota checks; seven-day audit records preserve the daily quota when redeemed/revoked invite rows are cleaned. Administrators can disable member issuance or pause all invitation creation. Password-only/pending/revoked member sessions cannot issue invitations; membership never grants administrative API access. This does not prevent social engineering, inviter/recipient relationship inference from existing metadata, theft of a live token, coercion, or malicious code supplied by a compromised origin. Invite abuse and the guided verification UX require independent review before release. No new anonymity or security certification is claimed. See ADR 0007 and the user guide.

## Optional generated local unlock secrets

New-browser setup can generate 32 browser-CSPRNG bytes encoded losslessly as a 43-character base64url passphrase. Generation is explicit, local and gated; missing/failing secure randomness has no predictable fallback. Existing vaults never offer regeneration. Users must reveal or successfully copy the value, then explicitly confirm they saved it before setup; regeneration clears that confirmation. Manual entry and existing Argon2id/AEAD vault protection remain available. No new server field, endpoint or crypto protocol is added.

A copied secret may remain in OS clipboard history/sync; revealed values, extensions, screenshots, browser memory/GC and malicious-origin code remain threats. The app makes no secure-erasure or independent security-verification claim. The setup generator is distinct from account passwords and recovery-kit keys and cannot recover an old vault. See ADR 0008 and the current test report. Overall release remains BLOCKED.
