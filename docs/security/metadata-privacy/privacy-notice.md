# Privacy notice — English / فارسی

## English

HAVEN encrypts message and attachment content between approved devices. Under correct endpoint/key custody and cryptographic implementation, the service database does not contain the keys needed to read that content. Your browser stores encrypted local history and cryptographic state. An unlocked or compromised device, a participant who saves content, or a compromised server that supplies hostile browser code can defeat these assumptions. View-once does not prevent screenshots or guarantee memory erasure.

HAVEN still knows account names, device identities, conversation membership, who submits each envelope, sequence/epoch and encrypted sizes. It needs these relationships for device trust, authorization, signed history, offline delivery, recovery and resource limits. A stolen database still reveals the social graph. The server and hosting provider can observe active requests; your ISP can see a connection to the service and traffic timing/volume. This is not network anonymity.

New messages use bounded MLS padding that reduces length precision; it does not hide their existence, timing, approximate size, attachments or sender relationship. Old clients may still send unpadded messages. Exact server acceptance time is no longer included in message API responses. Redundant ACK/upload/session time fields and an unused receipt table are removed. Expired KeyPackage payload and device/claim associations are cleared while a replay-prevention digest remains. These improvements cannot retract information in an old backup or a previously captured response.

The service retains pending message ciphertext until eligible devices durably acknowledge it; it does not expire unsynchronized ciphertext just to save space. Eligible application ciphertext and its acceptance time can retire after the existing 24-hour grace. Signed history, control messages, account/device/membership relationships and checkpoints remain. Files have a seven-day maximum, abandoned uploads one hour, view-once active leases ten minutes, sessions twelve hours, and recovery challenges five minutes. Expired/consumed/revoked temporary records are collected in bounded passes normally every five minutes, so a backlog or failure can delay removal. Security audit records normally last seven days; sent notification rows one hour. See the engineering retention policy for exact conditions.

Typing, presence, notifications and read receipts are optional and off by default. Choosing typing/presence exposes the selected conversation's live activity to the server and peers; synchronizing a device is not proof that a person read a message. Authentication still associates requests with an account/device. Login ingress sees your address for short-lived keyed throttling, even though the supplied application does not put raw addresses in a database or log. Redis account-to-socket hints expire after two minutes without valid heartbeat refresh; this is not anonymous routing.

Logical deletion does not erase WAL, old database pages, backups, replicas, SSD remnants or provider snapshots. Backup expiration depends on the operator's reviewed policy and separately protected keys. No complete anonymity, physical deletion or protection against a compromised running service is promised. Independent review, physical devices and domestic-network production qualification remain outstanding; production is blocked.

## فارسی

HAVEN محتوای پیام و پیوست را میان دستگاه‌های تأییدشده رمزگذاری سرتاسری می‌کند. در صورت سلامت دستگاه‌ها، نگهداری درست کلیدها و صحت پیاده‌سازی رمزنگاری، پایگاه دادهٔ سرویس کلید لازم برای خواندن این محتوا را ندارد. تاریخچه و وضعیت رمزنگاری در مرورگر به‌صورت رمزگذاری‌شده نگهداری می‌شوند. دستگاه باز یا آلوده، عضو گفت‌وگو که محتوا را ذخیره می‌کند، یا سرور آلوده که کد مخرب به مرورگر می‌دهد می‌تواند این فرض‌ها را نقض کند. نمایش یک‌باره مانع عکس‌برداری از صفحه نیست و پاک‌شدن قطعی حافظه را تضمین نمی‌کند.

سرویس همچنان نام حساب، شناسهٔ دستگاه، عضویت گفت‌وگو، فرستندهٔ هر بسته، ترتیب و دورهٔ رمزنگاری و اندازهٔ دادهٔ رمزگذاری‌شده را می‌داند. این ارتباط‌ها برای اعتماد به دستگاه، مجوز دسترسی، تاریخچهٔ امضاشده، تحویل آفلاین، بازیابی و محدودیت منابع لازم‌اند. سرقت پایگاه داده همچنان می‌تواند شبکهٔ ارتباطی کاربران را آشکار کند. سرور و میزبان درخواست‌های زنده را می‌بینند؛ ارائه‌دهندهٔ اینترنت نیز اتصال به سرویس و زمان و حجم ترافیک را می‌بیند. این سامانه ناشناسی شبکه فراهم نمی‌کند.

پیام‌های جدید از پُرکردن محدود و استاندارد MLS برای کاهش دقت مشاهدهٔ طول استفاده می‌کنند. این کار وجود پیام، زمان، اندازهٔ تقریبی، پیوست یا ارتباط فرستنده را پنهان نمی‌کند. کلاینت قدیمی ممکن است همچنان پیام بدون این پُرکردن بفرستد. زمان دقیق پذیرش سرور دیگر در پاسخ API پیام نیست. زمان‌های اضافی تأیید دریافت، بارگذاری و نشست و جدول رسیدِ بدون استفاده حذف شده‌اند. پس از انقضای بستهٔ کلید، محتوا و ارتباط دستگاه و درخواست‌کننده پاک می‌شود و اثرانگشت لازم برای جلوگیری از استفادهٔ مجدد باقی می‌ماند. این تغییرها اطلاعات موجود در نسخهٔ پشتیبان قدیمی یا پاسخ ضبط‌شده را پس نمی‌گیرند.

متن رمزگذاری‌شدهٔ پیامِ همگام‌نشده صرفاً برای خالی‌کردن فضا منقضی نمی‌شود. پس از ثبت پایدار تأیید همهٔ دستگاه‌های واجد شرایط و مهلت موجودِ ۲۴ ساعته، محتوای پیام عادی و زمان پذیرش آن می‌تواند کنار گذاشته شود. تاریخچهٔ امضاشده، پیام‌های کنترلی، ارتباط حساب و دستگاه و عضویت و نقاط تحویل باقی می‌مانند. سقف عمر فایل هفت روز، بارگذاری رهاشده یک ساعت، مجوز فعال نمایش یک‌باره ده دقیقه، نشست دوازده ساعت و چالش بازیابی پنج دقیقه است. پاک‌سازی دوره‌ای معمولاً هر پنج دقیقه و در دسته‌های محدود انجام می‌شود؛ انباشت کار یا خطا می‌تواند حذف را عقب بیندازد. رویدادهای امنیتی معمولاً هفت روز و اعلان ارسال‌شده یک ساعت نگهداری می‌شوند.

نشانگر نوشتن، حضور، اعلان و رسید خواندن اختیاری‌اند و پیش‌فرض خاموش است. روشن‌کردن حضور یا نوشتن، فعالیت زندهٔ گفت‌وگوی انتخاب‌شده را به سرور و اعضا نشان می‌دهد. همگام‌سازی دستگاه دلیل خواندن پیام توسط انسان نیست. درخواست‌ها همچنان به حساب و دستگاه مرتبط‌اند. ورودی سرویس برای محدودسازی کوتاه‌مدت ورود، آدرس شبکه را می‌بیند، هرچند پیکربندی ارائه‌شده آن را در مدل پایگاه داده یا گزارش برنامه ذخیره نمی‌کند. ارتباط حساب و اتصال در Redis پس از دو دقیقه بدون تمدید معتبر منقضی می‌شود؛ این مسیریابی ناشناس نیست.

حذف منطقی، پاک‌شدن WAL، صفحه‌های قدیمی پایگاه داده، نسخه‌های پشتیبان، رونوشت‌ها، بقایای SSD یا تصویرهای میزبان را تضمین نمی‌کند. عمر نسخهٔ پشتیبان به سیاست اپراتور و حفاظت جداگانهٔ کلیدها وابسته است. ناشناسی کامل، حذف فیزیکی قطعی یا حفاظت در برابر سرور درحال‌اجرای آلوده ادعا نمی‌شود. بررسی مستقل، آزمون دستگاه واقعی و ارزیابی عملیاتی شبکهٔ داخلی هنوز لازم است و انتشار عملیاتی مسدود باقی می‌ماند.
