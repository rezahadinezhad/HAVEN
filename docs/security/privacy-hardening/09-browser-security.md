# Browser and release integrity

**IMPLEMENTED_AND_TESTED.** Source review found no use of dangerouslySetInnerHTML/eval/console payload diagnostics in the relevant application/worker paths. Contact labels, file names and messages render as React text; contact URL parser enforces trusted HTTPS/same origin/path, length and strict schema; sensitive fragments are removed. Existing secure cookies, exact Origin, CSRF, private worker/IndexedDB custody, vault generation fences and generic notifications remain.

Production proxy previously accepted syntactically IPv4-looking hosts such as 999.0.0.1/invalid ports when reflecting a WebSocket origin into CSP. `src/proxy.ts` now checks canonical octets and port range. Exact optional hostname support is preserved. Production nonce CSP keeps wasm-unsafe-eval for actual WASM compilation but does not allow general unsafe-eval/unsafe-inline. Development behavior is unchanged. The proxy test executes the actual module, rejects seven hostile/malformed hosts and checks unique nonce plus policy; an actual production browser page also inspects the policy.

The client profile cache was removed, stale account-bootstrap completions are fenced, preference initialization is corrected, and lock clears profile rendering/notice/error state. Existing vault format, worker termination, encrypted revision/atomic outbox persistence and pagehide/inactivity behavior remain. Real browser lock/offline/logout and native MLS compatibility tests support these selected properties. A production Next build/typecheck passes and rebuilds the offline service-worker asset revision. Source manifest is regenerated only after review; dependencies and crypto WASM binaries are unchanged because Rust protocol source is unchanged.

No signatures from production release keys were created, and no release gate was opened. `scripts/release-gate.py` still exits 1 with BLOCKED; normal `haven/settings.py` retains CRYPTO_READY=False. The separately existing loopback-only integration setting is used only for synthetic tests and was not widened.

CSP/TLS and in-app signature checks do not solve hostile-origin code delivery. A compromised origin can serve JS/WASM that steals unlocked secrets. Independently distributed, reproducibly built and externally verified signed clients are a different future trust boundary and are not implemented here. Physical browsers, complete XSS/extension matrices, and independent application/cryptographic review remain open.
