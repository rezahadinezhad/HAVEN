# Security review and authoritative sources

This is an implementation self-review, not an independent security/cryptographic audit. Reviewed against the clean baseline and final code paths, generated contracts, bounded failures and successful reruns. No new cipher, anonymous mailbox, blinded credential, relay/provider, or MLS suite change was introduced.

| Foundation (checked 2026-11-03) | Standard/library property | HAVEN integration obligation | Exercised / remaining |
|---|---|---|---|
| [Django 5.2 signing](https://docs.djangoproject.com/en/5.2/topics/signing/) | Detect signed value modification; timestamp expiry with max_age; signing is not encryption | Domain salt, exact device/generation/restore-epoch scope, bounded input, approved caller, expiry/revoke/account fences and secret custody | Forge/swap/expire/revoke/restore tests plus real first contact; no general constant-time discovery proof |
| [PostgreSQL 16 privileges](https://www.postgresql.org/docs/16/ddl-priv.html) and [views](https://www.postgresql.org/docs/16/sql-createview.html) | SQL table and column grants restrict an unprivileged principal; ownership bypasses ordinary ACL restrictions | Independent LOGIN, no inherited/owner/admin capabilities, owner view with fixed projection, revoke column as well as table ACLs, deployment credentials actually separated | Actual login denials/worker subprocess, column-grant scrub; rendered Compose; full production deployment NOT_RUN |
| [OWASP HTML5 storage guidance](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html) | Same-origin JavaScript can read localStorage; untrusted data cannot become authentication authority | No profile/role cache, UUID-only unlock locator, encrypted vault custody and explicit hostile-origin limit | Locked storage/offline/logout/browser tests; hostile origin still defeats unlocked custody |

| Locally installed Next 16.4.3 docs: proxy and content-security-policy | Nonce-based production policy, development-only general unsafe-eval, dynamic rendering | Canonical reflected host, unique per-request nonce, WASM compatibility, no untrusted HTML, preserve worker/vault locking | Actual proxy hostile-host test, production build and browser CSP; no origin-trust solution |
| [libsodium XChaCha20-Poly1305](https://doc.libsodium.org/secret-key_cryptography/aead/chacha20-poly1305/xchacha20-poly1305_construction) media implementation | AEAD authenticity/confidentiality for correctly used key/nonce/AAD | Unique existing nonce scheme, v1 unchanged, v2 binds sizes/version/scope/index/count; validate length/padding before Blob; quota all ciphertext | Real sodium legacy/new negatives and actual MLS/SQL media/view-once; not external cryptographic integration analysis |
