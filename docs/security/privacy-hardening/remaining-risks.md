# Remaining risks and qualification gaps

- **Active social graph remains reconstructable by a fully privileged PostgreSQL attacker**, through User/Device/Membership/Conversation/Sender and signed genesis/full-roster transitions, ACKs, media ledgers and quota keys. No sender anonymity or unlinkable routing is claimed.
- A main runtime/hosting compromise sees current authenticated processing, application secrets and routing, and can serve hostile JS/WASM to steal unlocked client secrets. CSP/TLS/profile encryption cannot solve this trust boundary.
- Old backup/WAL/replica/provider snapshots, old browser/client copies and prior live observations persist. Logical deletion is not physical erasure. No automatic backup destruction occurred.
- Notification isolation narrows only that credential. API and retention worker still hold broad DB access; backups/migration/bootstrap remain privileged. The notification view reveals pending recipient associations; the worker knows routing secrets and can suppress hints. No general PUBLIC/inherited/custom-host policy audit beyond supported provisioning is claimed.
- Redis HMAC group keys hide direct UUID strings only from observers lacking the key. Stable pseudonyms, routing topology, timing, rates and optional event payloads remain correlatable. Rotation requires the documented staged publisher/drain process; initial raw-group upgrade is coordinated.
- Introductions are forwardable bearer links lasting 24h, distinct from one-use signup invitations. Old unrelated bare-UUID cards require new links. Historical peers retain certificate access. Restore epoch must be changed before reopening a rolled-back DB; automatic/global rollback detection remains unsolved.
- Media buckets reduce precision and incur explicit bounded overhead. File class/count/timing, sender/recipient and consumption metadata remain visible. Old attachments retain old precision; old v1-only frontends need upgrade for v2 file events. Malicious recipients can retain/capture plaintext and disclose size; view-once does not prevent screenshots.
- Local UUID/index/revision/preference metadata remains outside encrypted content. A compromised browser/extension or active unlocked session can observe data. Strict lock behavior is not mobile secure hardware or an origin-independent signed client.
- Historical graph retirement is specification only. Current protocol lacks all-party signed finality and sufficient offline/recovery/rollback guarantees for destructive removal. No status flag or cascade is presented as successful retirement.
