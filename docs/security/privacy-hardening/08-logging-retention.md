# Logging, retention and backups

**IMPLEMENTED_AND_TESTED** for the named existing controls and new configuration-redaction changes; no claim of erased historical records.

Reviewed Nginx configs, Django/DRF error handler/middleware, Uvicorn launch, PostgreSQL command flags, Redis persistence, workers, aggregate observability and backup tools. Supplied ingress already disables request/error logs and body spooling; API request/security/SQL/Uvicorn diagnostics are suppressed; workers emit aggregate/static failure text. AuditEvent already has only actor, fixed category, opaque target and timestamp. Metrics have bounded aggregate minute keys and short expiry, no account/path/IP labels. Redis persistence is disabled. These are existing protections, not new accomplishments of this pass.

New routing credentials are generated into protected config and included in installer Runner redaction, including an optional previous key. Contact grants use fragments/header, not API query strings, and no new exception logging or telemetry payload is introduced. New worker no longer receives main credentials/certificate mount. Failure to maintain privacy remains observable via aggregate `privacy:maintenance` state (900-second expiry), static worker failure output and queue/aggregate health; security audits are not indiscriminately deleted.

Retention remains: audit seven days; sessions/recovery/invitations expire/revoke/consume; expired pending enrollments are replay-safe tombstoned; expired KeyPackages keep permanent digest markers; sent outbox rows retire after one hour; media seven days/abandoned upload one hour; expired view-once lease capability fields scrub; application ciphertext only after all eligible durable ACKs plus 24-hour grace. Unsynced ciphertext, signed control/history, ACK cursors, quotas and permanent replay/view-once tombstones are not deleted by this work. Existing lock/recheck race tests remain in the backend regression.

PostgreSQL dumps, WAL/replicas, filesystem/provider snapshots, diagnostic overrides, browser extensions and old archive copies remain independent. Row retirement is not physical erasure; server-held keys do not protect from a fully compromised runtime. Existing separately encrypted backup/recovery-key custody is preserved. No real archive purge/rotation or backup-key destruction occurred. A new full encrypted backup/restore drill was NOT_RUN; the current migration test uses an isolated pre-upgrade synthetic schema.
