## IP TLS and PKI

PUBLIC_IP_TLS requires a publicly trusted CA supporting actual iPAddress SAN issuance. Verify current issuer policy at issuance; Let's Encrypt IP certificates are 160 hours, not months. Renew before expiry and monitor each endpoint. Outage may prevent outside renewal; never bypass verification. `make certificate-check` uses explicit trusted CA and IP verification. Browser rejection tests cover an untrusted root and a deliberately expired correct-IP leaf.

For EMERGENCY_PRIVATE_PKI, use an isolated controlled workstation, never CI/server. `make pki-create-offline-root` requires explicit manual isolation confirmation. Root procedure produces a protected encrypted signing key; `infrastructure/pki/issue-intermediate.sh` requires protected root/intermediate paths and passphrase entry, issues a 180-day pathlen-0 issuer and refuses overwrite. Keep both signing keys off servers. Generate leaf keys/CSRs on each server; sign actual IP SAN leaves using `issue-ip-leaf.sh`. Leaf validity is 30 days and the issuer must have at least 30 days left. Assemble leaf then intermediate chain as server leaf.crt. Transfer only public certificates/CSR and the appropriate server's leaf private key; do not distribute CA private keys.

Record out-of-band root fingerprint, certificate serials, SANs, validity windows and an offline inventory. Check server key permissions and root-free mount contents. The dashboard certificate date check is not chain/reachability verification. Private root installation increases trust scope. iOS requires explicit full trust after profile installation; Android/Chrome behavior must be physically demonstrated on supported versions. Do not send unknown root downloads or instruct warning click-through.

Clock policy: TLS validity and KeyPackage lifetimes require accurate device/server clocks. Prepare trusted time before isolation, monitor drift against independently verified sources, and stop onboarding if validity cannot be established. Never extend time by disabling certificate checks. Offline CRL/OCSP reachability is not assumed; maintain incident cards and short issuance lifetimes. Root compromise requires removal/replacement of trust anchors on every device; leaf/intermediate compromise requires revocation/rotation and independently communicated replacement evidence. Leaf rotation alone cannot repair a compromised root.

## Monitoring and incidents

After independently verifying an endpoint/CA, use `manage.py check_endpoint https://ACTUAL_IP --ca-file /protected/public-roots.pem --tls-profile EMERGENCY_PRIVATE_PKI --priority 1` (or PUBLIC_IP_TLS). It probes exact-IP TLS/health without redirects or verification bypass, then records the timestamp. This is an operational probe, not independent identity/phone/carrier validation. Registered endpoints and current origins appear in admin status; they never authorize an automatic client switch.

The admin dashboard exposes counts, pending notification outbox, ciphertext usage, DB/Redis checks, certificate dates, operator-recorded backups/releases and manual-fencing status. It contains no plaintext chat browser. The dashboard also reports bounded local request/error/latency buckets, approximate expiring WS leases, API-process CPU/RSS, API-filesystem free bytes, database size and notification age. Counters retain 60–120 seconds and no user/content/IP labels; leases expire after 70 seconds. API filesystem/CPU are not whole-host or database-volume measurements. Production monitoring/SLO, 500-session load/error budgets and telemetry qualification remain acceptance work. Ingress access and error request logs are disabled because Nginx error records may include invitation URLs. Use health/error counters; enable temporary diagnostics only with isolated synthetic traffic. Application logs contain no access payloads; investigate with bounded opaque incident IDs rather than dumping requests/keys/cookies.

For Redis outage, HTTP reads on existing approved sessions preserve durable messages; writes/rate-limited auth can fail closed. Restart Redis and reconnect/synchronize. For DB unavailability, no successful ACK is returned. On signed history/epoch/storage conflict stop sending, preserve the encrypted local vault and investigate; do not reset cursors or overwrite state. On compromised account/admin revoke sessions/devices, pause groups/invites, perform authorized removals/rekey, and independently verify replacements. On compromised application origin assume client keys/plaintext may have leaked; merely restoring the server does not repair them.

No complete network route, physical-power, carrier-blocking, malicious-origin or endpoint-compromise guarantee exists. Keep printed endpoint/trust/incident procedures and qualify the actual infrastructure with the intended community before any high-risk classification.
